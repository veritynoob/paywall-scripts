        Rule syntax reference
        

          

            A site entry runs when the tab URL matches one of its patterns, then applies its rules in
            order. Patterns use Chrome match-pattern syntax.
          

          

            
              
typekeyswhat it does

            
            
              
csshide[], cssinject a <style> at document_start

              
cookiecookies[{name,domain}]delete cookies so the meter resets (runs in the worker)

              
storagelocal[], session[]clear localStorage / sessionStorage keys (exact or prefix)

              
textselectors[], phrases[]strip leftover paywall wording from text nodes

              
unhideselectors[], attrs[]remove hidden / aria-hidden / inert from real content

              
untruncateselectors[], attrs[]drop truncation flags (isAccessibleForFree=false)

              
clickselectors[], tries, gapauto-click “Continue reading” style buttons

              
blockScriptspatterns[]stop matching <script src> from loading

              
nukeSelectorselectors[]hard-remove matching elements as they appear

              
redirecttoUrl, when[], onlyIfGatedsend the tab elsewhere — the answer to a server-side wall

            
          

          

            Client-side paywalls only. Nothing here can fetch a body the server refused to send — for
            those, use a redirect rule to an archive copy.
